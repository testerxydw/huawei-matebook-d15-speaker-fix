# 2026-07-27 华为 MateBook 扬声器修复调试记录

## 硬件/驱动事实（已实测确认）
- 机型：BoF-XX（华为 MateBook，与 BOD-WXX9 同架构，ES8336 codec + HWSP0001 功放）
- 扬声器功放 = HWSP0001（I2C 总线 4，地址 0x58/0x5B），只驱动扬声器；耳机走 ES8336 独立耳机路径
- 验证：写功放 `0x01=0x00` 后**扬声器静音、耳机照常响** → 功放软静音只影响扬声器，可行！恢复写 `0x01=0x69`

## 插孔检测彻底失效（用户空间无任何信号）
- gpio-81 (ESSX GpioInt)：恒定 hi，15 秒轮询采样零翻转 → 不是 jack 检测线
- /dev/input/event10（input23 sof-essx8336 Headset）：真实节点是 event10，但插拔时无 EV_SW 事件（驱动 jack detect 卡死）
- ALSA `Headphone Jack`(27/28)：永远 off
- ES8336 codec I2C 寄存器：用户态全读失败（被 SOF 驱动锁总线）
- udev / pactl subscribe：插拔无事件
- 完整 GPIO 列表只有 gpio-0(speakers-enable), gpio-81(ESSX GpioInt), gpio-173(TPD0) —— 无 headphone 使能 GPIO，无独立 jack input 线

## 根因（来自 LKML 补丁）
- LKML 补丁 `ASoC: Intel: sof_es8336: Fix headphone GPIO inversion`（作者 Tagir Garaev，测 BOD-WXX9）：
  驱动 bug = 插耳机时把 gpio_speakers 与 gpio_headphone 设成**相同值**，导致都响；补丁改为反相 `!speaker_en`
  该补丁需重编译 snd-soc-intel-sof-es8336 模块，不能仅靠 modprobe 参数

## 当前脚本状态（huawei-speaker-mute.sh）
- 之前逻辑基于错误的 gpio-81 检测 + Speaker Switch 控件（实测 Speaker Switch=off 不能静音扬声器，无效）
- 服务已停；功放 0x01 已手动恢复 0x69

## 待决策方案
A. 用户空间功放软静音(0x01) + 手动切换命令（立即可用，但无自动检测）
B. 重编译打补丁的内核驱动（恢复真正自动，但 jack detect 在本机仍可能死，因为 gpio-81 恒定）
- 需用户确认走哪条；并对比插拔态功放寄存器看有无 jack 状态位（最后希望）
