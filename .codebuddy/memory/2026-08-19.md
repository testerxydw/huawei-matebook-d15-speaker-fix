## 【核心根因+已修复】脚本 jack 监听"插入后才打印拔耳机日志"的缓冲 bug
- **现象**：拔耳机时脚本不打印/不设0x69，插入耳机后才同时打印"拔耳机(0x69)"+"插耳机(0x00)"，导致拔耳机切扬声器始终无声。用户多次确认此规律。
- **排查**：独立 os.read 监听器证明 event10 事件**实时到达内核**；es8316 中断正常；重启服务也复现滞后（非进程累积）；停掉我的监听器后仅脚本监听仍滞后 → 排除干扰/进程老化。
- **根因（已确认）**：脚本 Python 监听用 `f = open(dev,"rb")`（**带缓冲**文件对象）+ `select.select([f])` + `f.read(sz)`。select 监控底层 fd，但 `f.read()` 首次会把**多个 input_event 一次读入 Python 缓冲**，只返回 24 字节；剩余事件留在缓冲但**底层 fd 已空**，select 阻塞。直到下次插入产生新事件，select 才唤醒，脚本从缓冲消费积压的"拔耳机"事件 → 表现为"插入后才打印拔耳机"。
- **修复（最小改动，已部署 /opt）**：改用 `os.open(dev, os.O_RDONLY)` + `os.read(f, sz)` + `os.close(f)`（无缓冲），select 与 read 操作同一底层 fd。修改 `huawei-speaker-mute.sh` 行 148/162/164-165。部署后用户拔插**实时响应**（19:02:38 拔→0x69, 19:02:48 插→0x00），修复成功。
- **遗留**：源码已改，未提交。另有 `read_initial_jack_state`(行96/99)本就用 os.open 正确。
- **教训**：对字符设备(/dev/input)用 select+read 必须无缓冲，否则缓冲与 select 监控不一致导致事件消费延迟。

## bind mount 不能去掉（重要）
- 用户问：现在用原版，能否去掉 `/etc/fstab` 里的 bind mount（认为原版在不可变系统里）。
- **结论：不能去掉**。当前内核 `6.18.38` 的 es8316 模块**不在 ostree 不可变系统里**——ostree 里只有旧内核（6.6.120/6.12.65/6.18.36）的 es8316，没有 6.18.38 的。6.18.38 的模块只存在于 `/persistent/snd-soc-es8316.ko.zst`（inode=12，bind mount 提供）。

- **补充（用户追问"配置前系统有驱动吗/覆盖还是删除"）**：bind mount 是**覆盖(隐藏)不删除**；但关键：**当前 6.18.38 内核的 es8316 模块本来就不在 ostree 里**（ostree 部署 14d8101b 的 /usr/lib/modules/ 下根本没有 6.18.38 目录）。系统 3 个内核(6.12.65/6.18.36/6.18.38)，es8316 模块都非 ostree 自带，是内核升级/包安装放到可写层(overlay 上层或 /persistent)。6.18.36 的模块在 /usr/lib/modules/6.18.36（inode 7222888 非 bind mount，24982 字节），6.18.38 只在 /persistent（24975 字节，bind mount）。用户"配置前有驱动"的记忆对应旧内核 6.18.36 时代。
