# 2026-07-28 当前脚本 vs 初始版本差异分析 + 故障根因

## 用户最新诉求
分析当前 `huawei-speaker-mute.sh`（HEAD e7719cf，自动版）与初始版本（9a9b5d3）差异，修复音频切换异常：
- 开机插耳机 → 之后插拔扬声器都无声
- 开机没插耳机 → 之后插拔扬声器一直有声
要求实现：拔耳机扬声器发声 / 插耳机仅耳机响 / 拔耳机先静音待用户调音量再响。

## 差异结论
初始版与当前版**核心逻辑完全相同**：都依赖 `Headphone Jack` 控件 + `alsactl monitor` 事件来切功放 GPIO。
当前版仅是“健壮性/适配”增强，与故障无关：
- 参数自动探测（I2C/JACK/GPIO 从 DSDT）+ 环境变量覆盖
- PipeWire 音量控制（runuser + wpctl），拔耳机跳变时音量清零 3 次（unplug_volume_guard）
- transition 跟踪：仅状态变化才切 amp（避免每次事件拉起/杀 gpioset）
- set_amp：kill 旧进程 + wait + sleep 0.15 + EBUSY 重试 4 次；仅 val=1 时 reinit_amp
- GPIO_LINE 回退 145、I2C_BUS 回退 4（适配 BoF-XX）

## 根因（关键）
`Headphone Jack` 在开机驱动 probe 时读取一次真实物理状态后**冻结**，之后不再更新；
`alsactl monitor` 也只发 `DAC Playback Volume` 事件，从不发 jack 事件。
→ `apply()` 只在开机时按冻结值设置一次 amp 状态，之后所有事件读到的都是冻结值，amp 永不改变。
完美解释两个症状：
- 开机插耳机 → 开机 jack=on → amp 关 → 无声；拔掉也不变 → 一直无声
- 开机没插耳机 → 开机 jack=off → amp 开 → 有声；插拔也不变 → 一直有声
用户要求的 1/2/3 全依赖“运行时插拔被实时感知”，而本机用户空间**无任何 jack 信号**
（gpio-81 恒定、event10 无事件、acpi 无、pactl 无、ALSA jack 冻结）。
→ 调整初始化顺序/alsactl 监听/GPIO·AMP 时序都**无法修复**，因为根本没有插拔信号可响应。

## 可行路径（待用户决策）
A. 内核驱动补丁（LKML sof_es8336 GPIO 反相补丁）：唯一能实现自动切换的路径；需本机编译对应内核模块；BOD-WXX9 验证有效，BoF-XX jack 检测硬件疑似不同，存在不确定性。
B. 用户空间手动静音/取消静音（功放软静音 0x01=0x00/0x69，已实测可用）+ 快捷键：立即可用，非自动。
C. 折中：开机按冻结值最佳初始化 + 保留手动 mute/unmute/status + 文档说明限制。

## 最终修复方案（已验证成功，2026-07-28 下午）

用户实测确认：**拔耳机扬声器无声（音量0）、插耳机扬声器仍无声、拔耳机调音量后正常播放**。修复成功。

### 采用的方案
放弃内核补丁（曾建 `es8336-jack-invert/` 编 es8336 `JD_INVERTED` 反相模块，后删除），改用纯用户空间脚本修复：
- 仅改 `huawei-speaker-mute.sh` 的 `set_amp()`：插入耳机（`val=0`）时写 HWSP0001 软静音寄存器 `0x01=0x00`（只静音扬声器、耳机经 ES8336 独立路径不受影响，已实测）；拔掉（`val=1`）时保持 gpio-145 常开 + `reinit_amp()` 恢复 `0x01=0x69` 并使能寄存器。
- 新增 `mute`/`unmute`/`status` 子命令（手动控制/排障）。
- 安装到 `/opt/huawei-speaker-mute.sh`（因 `/usr/local/bin` 不可写），服务 `huawei-speaker-mute.service` 开机自启。

### 内核无关性验证（关键结论）
- `git diff` 仅改脚本 + README；`es8336-jack-invert/` 已删，无残留。
- 无自定义内核模块：`/updates` `/extra` 下无 `es83xx`；`dkms status` 仅 `deepin-anything`（无关）；`snd-soc-es8336.ko.zst` 仍在内核自带路径。
- 内核配置对比：运行 `/proc/config.gz` 与 `/boot/config-$(uname -r)` `diff` 结果 **完全一致（KERNEL_CONFIG_IDENTICAL）**；`CONFIG_MODULE_FORCE_UNLOAD` 未置位、`CONFIG_SND_SOC_ES8336=m` 均为发行版默认。
- **结论：修复完全独立于内核层，可即时回退、零残留。**

### 可移植性评估
- 复用框架（硬件无关）：`alsactl monitor` 监听 `Headphone Jack` + PipeWire `wpctl` 音量保护 + systemd 常驻。
- 设备相关：`detect_i2c()` 依赖 `i2c-HWSP0001:00` 节点、`set_amp()` 的 `0x01=0x00`/`reinit_amp` 寄存器序列/`0x58,0x5B`、DSDT `GNUM()` 解析的 gpio 线号，均为 HWSP0001/BoF-XX 专属。
- 移植条件：功放需 I2C 可达且有软静音寄存器；耳机路径独立于扬声器功放；存在可监听的插拔事件源。满足则替换上述寄存器/地址即可复用框架。
- **结论**：`huawei-speaker-mute.sh` 是 HWSP0001 成品修复，非通用工具，但其架构可作同类设备模板。README.zh-CN.md / README.md 已补第 6、7 章（内核无关性验证 + 可移植性评估）。
