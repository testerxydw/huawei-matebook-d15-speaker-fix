## 1. 第一次审计结论摘要（冗余视角）

存在冗余，但绝大多数是**防御性 / 隔离性 / 跨语言**冗余，运行时未造成浪费：

- **最外层 2s 纯轮询** 与 `jack_monitor` 内置 5s 轮询是同一机制的两份实现（靠 `MONITOR_RUNNING` 互斥，运行时不同时跑）。
- **静音写入点** 在 `reinit_amp 0` 与 `set_amp` 兜底处各一份（`0x01=0x00`）。
- **`read_jack`** 有 bash 与 python 两份实现（语言边界导致）。
- **GPIO 拉起逻辑**（`pkill + start_gpioset`）分散在 4 处（启动前 / `start_gpioset` / `health_check` / `set_amp` 重试）。
- **`health_check` 与 `apply`** 决策逻辑重叠（子 shell 无法共享 `PREV/CUR_AMP`，属必要隔离）。
- 日志印证：BoF-XX 上 `alsactl monitor`（次通道）与 2s 兜底**从未真正接管**，属常驻安全网。

## 2. 第二次审计结论摘要（质量属性视角）

### 2.1 性能（Performance）
- 主监听 `jack_monitor` 每 5s `subprocess` 调一次 `amixer`；`health_check` 每 60s 调 2 次 `i2cget`——开销可忽略。
- `reinit_amp` 每次约 24 次 `i2cset` + 2 次 `i2cget`，仅在插拔跳变/自愈时触发，频率低，可接受。
- **明显开销点**：`unplug_volume_guard` 每轮 3 次调用 `set_pw_vol`，每次 `set_pw_vol` 都 `runuser -u $PW_USER -- wpctl`，即每次 unplug 产生 **9 次 runuser/PAM 会话**（日志中可见 session opened/closed 刷屏）。属**性能+日志噪音**问题，不影响正确性。
- 结论：性能总体良好，唯一可优化点是 `runuser` 会话抖动。

### 2.2 可维护性（Maintainability）
- 逻辑分散（GPIO 恢复 4 处、静音写入 2 处、`read_jack` 2 语言）。
- **双源真相**：寄存器初始化值同时存在于 `amp_0x58_init.txt` / `amp_0x5B_init.txt` 与 `reinit_amp` 内联 `REGINIT` heredoc；脚本实际用内联值，`.txt` 仅作参考。二者**可能漂移**，是主要维护风险。
- 顶层流程顺序化、较长（~728 行），但函数划分尚可。

### 2.3 健壮性（Robustness）
- 缺失 `i2c-HWSP0001` → 退出；缺失 jack 控件 → 重试 15×2s 再退出；`reinit_amp` 读回校验 + 重试 3 次；`health_check` 自愈——健壮性良好。
- input 设备中途消失时 `jack_monitor` 尝试重开，失败则降级到 alsactl/兜底，链路完整。
- 无明显健壮性缺陷。

### 2.4 可读性（Readability）
- 中文注释清晰；诊断长行已拆行；但存在密集 bash（`REGINIT` 的 `case` 续行、`pgrep -f` 正则）、魔法数字（0x58/0x5B、0x01、0x69/0x00、间隔常量）。
- 整体可接受，常量集中可进一步提升。

### 2.5 可测试性（Testability）
- 长驻守护进程，难以单元测试；`tools/` 诊断脚本支持手动验证；`mute/unmute/status` 子命令便于人工核查。
- 缺少自动化的 dry-run / 单测骨架。

### 2.6 安全性 / 最小权限（Security）
- 以 root 运行（硬件访问必需）；PipeWire 音量操作用 `runuser` 降权到桌面用户——最小权限实践正确。
- `i2cset -f` 强制访问属必要；不解析不可信输入、无网络——攻击面小。

### 2.7 可移植性 / 兼容性（Portability）
- `install.sh` 已覆盖 apt/dnf/pacman/zypper；`gpiod`/`libgpiod` 包名差异已处理。
- DMI 仅识别 `BoF*`/`BOD*`/`BOH*`，未知机型保守默认 `NEEDS_GPIO=1`。
- I2C 地址/寄存器对 HWSP0001 硬编码（设计如此，文档已说明），框架可移植、常量设备相关。

## 3. 重构方案（含收益与风险）

> 每项均标注**收益**与**风险**；建议**分批实施、每批带本机 5 场景验证**。

### R1. 收敛插拔监听为单一轮询实现
- **现状**：最外层 `while sleep 2; apply` 与 `jack_monitor` 内置轮询重复"读 jack→apply"。
- **做法**：主/次通道退出时，复用 `jack_monitor` 的纯轮询模式（删除独立 2s 循环）。
- **收益**：消除重复逻辑；减少常驻进程；监听语义单一。
- **风险**：需保证纯轮询模式行为与原兜底一致（初始 emit、间隔）；回归测试须覆盖 input 设备缺失场景。

### R2. 收敛 GPIO 供电恢复为单一函数 `ensure_gpio_power()`
- **现状**：4 处 `pkill + start_gpioset`。
- **做法**：抽出 `ensure_gpio_power()`，启动 / 健康检查 / 重试统一调用；`NEEDS_GPIO=0` 时直接返回（BoF-XX 行为不变）。
- **收益**：消除逻辑分散，降低"改一处漏一处"风险。
- **风险**：需注意 `health_check` 在子 shell 中调用语义与主进程一致；避免引入共享全局状态依赖。

### R3. 统一 `read_jack` 为单一实现
- **现状**：bash 与 python 各一份 ALSA 读取解析。
- **做法**：让 `jack_monitor` 复用同一解析（如调用脚本暴露的解析函数 / 共享小工具），或抽成独立 `jack_read` 脚本。
- **收益**：避免跨语言实现漂移。
- **风险**：跨语言抽取增加少量复杂度；需保证 python 解析与 bash `sed` 结果一致。

### R4. 统一静音写入点
- **现状**：`reinit_amp 0` 与 `set_amp` 兜底都写 `0x01=0x00`。
- **做法**：静音分支只走 `reinit_amp 0`；兜底直接写保留为最后手段并显式注释。
- **收益**：写入路径单一，便于校验与排查。
- **风险**：移除兜底后极端 `reinit_amp` 异常会少一次尽力写入（影响极小，可保留注释说明）。

### R5. 消除寄存器初始化值双源真相
- **现状**：`amp_0x5X_init.txt` 与 `reinit_amp` 内联 `REGINIT` 各一份。
- **做法**：二选一为唯一来源——例如脚本启动时从 `.txt` 加载（需容错），或反之以内联为准并删除/标注 `.txt` 为生成物。
- **收益**：避免值漂移，单一维护点。
- **风险**：运行时读取 `.txt` 需处理文件缺失/格式错误；须先 `diff` 确认与当前内联值逐字节一致再切换。

### R6. 减少 `runuser`/PAM 会话抖动与日志噪音
- **现状**：`unplug_volume_guard` 每次 unplug 触发 9 次 runuser 会话（日志刷屏）。
- **做法**：在单次 `runuser` 会话内完成 3 次 `wpctl set-volume 0`（或合并为一次调用 + 短 sleep 重试）。
- **收益**：降低 unplug 开销与 PAM 日志噪音（贴合日志中观测到的 session 抖动）。
- **风险**：PipeWire 可能在连续 set-volume 间恢复音量；减少次数须验证仍能压过 WirePlumber 竞态（建议在 BoF-XX 实测爆音）。

### R7. 常量集中化 / 配置外置（可选）
- **做法**：把 I2C 地址、寄存器、间隔等提到顶部 config 块或独立 `.conf`。
- **收益**：可读性与可移植性提升；适配其它功放改一处。
- **风险**：改动面较大，需回归测试；确保与现有自动探测默认值完全一致。

### R8. 增加轻量 dry-run / 自测模式（可选）
- **做法**：加 `--dry-run` 打印将执行的操作而不实际写 I2C。
- **收益**：提升可测试性，便于 CI / 手动验证，不依赖真实硬件。
- **风险**：需保证 dry-run 不遗漏副作用；开发成本。

## 3.5 优先级排序（收益从大到小 / 影响从小到大）

> 供决策"哪些要优化"参考。收益=对维护/性能/可读等的改善；影响=风险与改动面（低→高）。

### 表 A：按收益从大到小
| 排名 | 项 | 收益 | 说明 |
|------|----|------|------|
| 1 | R5 消除寄存器双源真相 | 高 | 当前主要维护风险（`.txt` 与内联 `REGINIT` 可能漂移） |
| 2 | R1 监听单一化 | 中高 | 消除核心重复的轮询逻辑 |
| 3 | R2 GPIO 恢复收敛 | 中 | 消除 4 处分散的 `pkill+start_gpioset` |
| 4 | R6 减少 runuser 抖动 | 中 | 性能+日志噪音，且日志已实测到 session 刷屏 |
| 5 | R7 常量集中 | 中 | 可读/可移植，但改动面大 |
| 6 | R8 dry-run 模式 | 中 | 提升可测试性（新增，可选） |
| 7 | R3 统一 `read_jack` | 低 | 跨语言重复，漂移概率低 |
| 8 | R4 统一静音写入点 | 低 | 兜底写入极少触发，收益最小 |

### 表 B：按影响（风险/改动面）从小到大
| 排名 | 项 | 影响 | 说明 |
|------|----|------|------|
| 1 | R8 dry-run | 低 | 纯新增 flag，不影响现有路径 |
| 2 | R6 runuser 抖动 | 低 | 仅改 `unplug_volume_guard` 局部 |
| 3 | R4 静音写入点 | 低 | 仅删/注释一处兜底 |
| 4 | R2 GPIO 收敛 | 低~中 | **BoF-XX 上 `NEEDS_GPIO=0` 全为 NO-OP**，运行时零变化，仅 BOD/BOH 有效 |
| 5 | R3 `read_jack` | 中 | 跨语言抽取 |
| 6 | R5 双源真相 | 中 | 切换数据源前需 `diff` 校验一致性 |
| 7 | R1 监听单一化 | 高 | 动核心监听链路，回归风险最高 |
| 8 | R7 常量集中 | 高 | 全局常量，需全量回归 |

### 推荐实施顺序（收益/风险比，高收益+低影响优先）
1. **R6** — 中收益 / 低影响（日志已实测到症状，见效直观，最该先做）
2. **R2** — 中收益 / 低影响（BoF-XX 无运行时变化，纯维护性，安全）
3. **R5** — 高收益 / 中影响（主要维护风险，`diff` 校验后可做）
4. **R4** — 低收益 / 低影响（顺手做）
5. **R8** — 中收益 / 低影响（可选，提升测试性）
6. **R3** — 低收益 / 中影响（性价比低，可暂缓）
7. **R1** — 中高收益 / 高影响（核心监听重构，风险最高，放最后）
8. **R7** — 中收益 / 高影响（全局常量，改动面大，最后）

**建议**：前 4 项（R6→R2→R5→R4）收益可观、风险可控，最适合先优化；R1/R7 收益虽不低但影响大，建议确认整体稳定后再动。



- **分批**：建议 R1+R2+R4（收敛重复）为第一批；R5（双源真相）为第二批；R6（日志/性能）独立小批；R7/R8 视需要。

## 3.6 实施状态标记（是否影响主要功能）

> 主要功能 = 插拔自动静音/恢复（软静音寄存器 `0x01` + input event 监听 + 健康检查 + 防爆音音量保护），本机目标 **BoF-XX（`NEEDS_GPIO=0`）**。
> 原则：**动核心路径或改动面过大、风险高于收益的项，标记为「不做 / 暂缓」**。

### 标记为「不做 / 暂缓」（影响或高风险影响主要功能，或改动面过大）
| 项 | 标记 | 原因 |
|----|------|------|
| R1 监听单一化 | 暂缓 | 重构核心监听链路（input event + alsactl + 兜底轮询），回归风险最高，直接影响插拔检测这一主要功能 |
| R3 统一 `read_jack` | 暂缓 | 触及核心插拔状态读取（bash/python 双实现），且收益低，动核心读取不划算 |
| R7 常量集中 | 不做 | 全局常量改动面最大、影响范围最广，收益不紧急，暂不需要动全局 |

### 可安全实施（不影响主要功能）
| 项 | 原因 |
|----|------|
| R2 GPIO 收敛 | BoF-XX 上 `NEEDS_GPIO=0`，GPIO 路径全为 NO-OP，重构**零运行时变化**，纯维护性 |
| R4 统一静音写入点 | 仅删/注释极少触发的兜底写，主路径（`reinit_amp 0`）不变 |
| R5 消除双源真相 | 仅统一寄存器值来源，只要与内联值逐字节一致即不改功能；切换前需 `diff` 校验 |
| R6 减少 runuser 抖动 | 仅优化 `unplug_volume_guard` 的音量保护路径（次要安全层），核心静音/恢复（I2C 寄存器）不动；日志已实测到 session 刷屏症状 |
| R8 dry-run | 纯新增可选 flag，不影响任何现有路径 |

**建议先实施（均不影响主要功能，按收益/风险比）**：R6 → R2 → R4 → R5 → R8。R1 / R3 / R7 暂缓。

## 5. 整体收益与风险总结

**整体收益**
- 消除代码重复与双源真相（R1/R2/R3/R4/R5），显著降低维护负担与"改一处漏一处"风险。
- 减少 unplug 时的 `runuser`/PAM 会话抖动与日志噪音（R6），小幅提升性能与可观测性。
- 常量集中与 dry-run（R7/R8）提升可读、可移植与可测试性。
- **对外语义完全不变**：插拔联动、软静音、防爆音、健康检查等行为保持稳定。

**整体风险**
- **回归风险最高**：监听链（R1）与自愈（R2）改动最易引入"插拔失效"，必须在本机 5 场景充分验证。
- **跨语言抽取复杂度**（R3）与**双源真相切换**（R5）需先 `diff` 校验一致性，避免无声回归。
- **改动面控制**：R7 影响全局常量，宜放最后并全量回归。
- 建议：每批小步提交、保留回退能力（本方案本身不改内核、零残留，回退容易）。

> 本方案仅作规划，等待确认后再实施。
